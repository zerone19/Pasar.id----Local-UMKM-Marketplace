## Critical Issues

### 1. Tailwind CSS not wired up (likely breaks entire UI)
- **No `globals.css` found** in `src/app/` or anywhere in `nextjs-web/src/`.
- `layout.tsx` does **not** import any CSS file.
- Without `@tailwind base/components/utilities` directives somewhere, **none of the Tailwind utility classes work** — the entire design-system styling collapses to browser defaults.
- Tailwind config (`tailwind.config.ts`) only defines 5 colors (`primary`, `secondary`, `tertiary`, `background`, `cream`) and 2 font families (`sans`, `body`). It does **not** define the full design-system color palette from `DESIGN.md` (e.g. `surface-container-high`, `on-surface-variant`, `outline-variant`, `error`, `tertiary-fixed`, etc.) or the custom font families (`headline-xl`, `headline-md`, `label-md`, `body-sm`, etc.).
- **Result:** classes like `bg-surface-container-high`, `text-on-surface-variant`, `font-headline-md`, `shadow-organic`, `border-outline-variant` are unknown to Tailwind and produce no CSS. Only `bg-primary`, `text-primary`, `border-primary`, `bg-cream`, `bg-secondary`, `bg-tertiary`, and the two base fonts have any effect.

### 2. Material Icons not loaded
- Every page and component uses `<span className="material-icons">...</span>` extensively (search, cart, location, arrows, etc.).
- There is **no Google Fonts link, no `@fontsource` package, no CSS import** for Material Icons anywhere in the project.
- **Result:** icons render as literal text strings (e.g. "shopping_cart", "arrow_forward") or blank — not as icons.

### 3. Font configuration incomplete
- `DESIGN.md` specifies **Be Vietnam Pro** for headlines/body and **Work Sans** for labels, with specific weights/sizes per style (`headline-xl`, `headline-md`, `label-md`, `body-sm`, etc.).
- `tailwind.config.ts` only registers `sans: ["Be Vietnam Pro"]` and `body: ["Work Sans"]`.
- Pages use classes like `font-headline-md`, `font-label-md`, `font-body-sm`, `font-body-lg`, `font-headline-xl` — none of which exist in the Tailwind config.
- Cart and Stores pages use inline `font-[Be_Vietnam_Pro]` arbitrary syntax, which Tailwind does support — but that's the only font that works.

### 4. `_app.tsx` is orphaned (App Router / Pages Router mismatch)
- Project uses **App Router** (`src/app/` directory structure).
- `_app.tsx` is a **Pages Router** concept — Next.js App Router ignores it. It is dead code.
- Even if it were active, it would conflict: it wraps everything in `<div className="min-h-screen bg-background">` with its own `<Header />`, while `page.tsx` (home) and `products/page.tsx` also render their own `<Header />` and `<Footer />`. Double header, double main tags.
- **Recommendation:** delete `_app.tsx`. Move `<Header />` and `<Footer />` into `layout.tsx` so every page inherits them.

### 5. `layout.tsx` metadata is wrong
```ts
export const metadata = {
  title: 'Next.js',
  description: 'Generated by Next.js',
}
```
Should be `Pasar.ID` branding.

### 6. Header links to non-existent routes (→ 404)
Header (`Header.tsx` lines 31, 39, 47) and mobile menu link to:
- `/categories` — **no page exists**
- `/umkm` — **no page exists**
- `/about` — **no page exists**

Only `/` and `/products` actually exist. Clicking "Kategori", "UMKM Terdekat", or "Tentang Kami" gives a 404.

### 7. `/products` page — API field mismatch (product.store is always undefined)
**Frontend interface** (`products/page.tsx` line 16-19):
```ts
store?: {
  id: string;
  name: string;
};
```
**Backend** (`products.service.ts` line 10):
```ts
include: { category: true, seller: true }
```
The backend returns `seller`, not `store`. The frontend renders:
```tsx
{product.store && (
  <p className="...">Dari {product.store.name}</p>
)}
```
Since `product.store` is always `undefined`, the "Dari Toko X" line **never appears**. The field should be `seller` on the frontend, or the backend should include `store`.

### 8. `/products` page — price type mismatch
- Backend `Product` model has `price: number` (see `products.service.ts` line 24: `price: number`).
- Frontend interface declares `price: string`.
- Rendering code: `parseFloat(product.price)` — works at runtime because `parseFloat` coerces numbers, but the TypeScript interface is wrong. If the backend ever returns a string, `parseFloat` would silently produce `NaN`.

### 9. `/products` page — hardcoded backend URL
```ts
axios.get<Product[]>('http://localhost:3000/products')
```
Hardcoded to `localhost:3000`. Should use an environment variable (`process.env.NEXT_PUBLIC_API_URL` or similar) so it works in production and on different dev machines. The frontend runs on port 3001 per project context, backend on 3000 — this works locally but is fragile.

### 10. `/products` page — no `isActive` filter needed (redundant but not harmful)
Backend `findAll()` already filters `where: { isActive: true }`. Frontend also does `.filter(p => p.isActive)`. Redundant but not a bug.

### 11. Cart and Stores pages are stubs
- `cart/page.tsx`: Only a heading and a paragraph. No cart state, no items, no add/remove, no total.
- `stores/page.tsx`: Only a heading and a paragraph. No data fetching, no store list.

Both are placeholder pages with zero functionality.

### 12. Cart page uses `font-[Be_Vietnam_Pro]` arbitrary syntax while home page uses `font-headline-*` classes
Inconsistent font application. The home page uses design-system font classes (which don't exist in Tailwind config), while cart/stores use arbitrary font syntax (which does work).

## Minor / Style Issues

- **Home page hardcodes featured stores** (lines 127-129): `featuredStores` array with 2 entries — "Kriya Anyam Mbah Tarjo" and "Toko Jajanan Ayu". These are static, not fetched from the API. The `/stores` backend endpoint exists and could supply this data.
- **Home page categories are hardcoded** (lines 119-124): 4 categories match the spec (`Sayur Segar`, `Jajanan Pasar`, `Kerajinan Lokal`, `Daging & Ikan`). Icons used: `eco`, `favorite`, `handcraft`, `restaurant` — these are Material Icons that won't render (see issue #2).
- **No SEO meta tags** beyond the generic layout metadata. No Open Graph, no favicon configuration.
- **No `next/image` usage** — product images are rendered as empty `div` placeholders with a Material Icon fallback. No `public/` directory inspection was done, but no `<Image>` components exist.
- **No error boundary** — if a page crashes, there's no custom error handling beyond the inline error state in `/products`.

## What Works

- Route structure: `page.tsx`, `products/page.tsx`, `cart/page.tsx`, `stores/page.tsx` all exist at correct paths.
- `/products` page has full fetch/loading/error/empty-state logic — the client component pattern is correct.
- `Header.tsx` has responsive mobile menu toggle, search bar, cart badge, account icon — the interactive logic is sound (aside from icon rendering).
- Color values in `tailwind.config.ts` match `DESIGN.md` for the 5 colors that are defined.
- TypeScript interfaces are generally well-typed (aside from the `price: string` / `store` vs `seller` issues).
